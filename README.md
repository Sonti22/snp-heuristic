# SNP Heuristic: распределение дефицита

Python 3.10+, стандартная библиотека. После клонирования, из каталога репозитория:

```sh
python main.py
```

Команда читает оба CSV из `data/`, выводит отгрузки и остатки всех корректных
кейсов. В исходном **CASE_03 намеренно некорректные данные**: он отклоняется с
двумя объяснениями. Поэтому для поставленного набора код завершения **1 ожидаем**.
Исходные CSV сохранены без изменений. Каталог данных можно заменить:
`python main.py --data-dir /path/to/data`.

Коды завершения: `0` — все кейсы рассчитаны; `1` — хотя бы один кейс отклонён;
`2` — ошибка чтения или структуры входных файлов, расчёт не начат.
Отклонённый кейс не имеет плана: это не успешное распределение с нулевыми отгрузками.

## Правило

1. Меньший `priority` обслуживается раньше. Перепоставка запрещена.
2. Для каждой заявки считаются максимальная допустимая отгрузка и первая
   допустимая партия. Если первая больше максимума, заявка получает 0.
3. Внутри приоритета сначала резервируются первые партии по возрастанию их
   размера, затем по `request_id`. Это максимизирует число получателей в группе.
4. Остаток делится пропорционально **ещё доступному объёму до максимума** у
   допущенных заявок; квоты округляются вниз по кратности.
5. В порядке убывания отброшенной части квоты выдаётся по одной дополнительной
   кратности. Затем один проход в том же порядке раздаёт помещающийся кратный
   остаток до максимума. Во всех ничьих используется лексикографический ID.
6. Нераздаваемый старшей группе остаток переходит следующему приоритету.

Это эвристика с приоритетом охвата точек внутри группы. Она не гарантирует
оптимальную загрузку запаса или точную пропорциональность исходному спросу.
Пример CASE_02: сначала `30/30/30/0`, затем остаток 10 получает R-201;
итог `40/30/30/0`. Причины выбора и ограничения — в [REPORT.md](REPORT.md).

## API и устройство

```python
from allocator import Request, allocate

plan = allocate(10, [Request("A", priority=1, demand_qty=8),
                     Request("B", priority=1, demand_qty=8)])
assert plan == {"A": 5, "B": 5}
```

- `allocator.py` — модель, валидация и весь алгоритм: 97 физических строк,
  включая комментарии и пустые строки, при лимите 150.
- `main.py` — проверка структуры CSV и CLI; имена периода/позиции/локаций — метки.
- `tests/` — ожидаемые планы, собственные сценарии, ошибки, проверка CLI и
  300 воспроизводимых случайных наборов. У каждого теста есть строка с объяснением.
- `REPORT.md` — журнал решений, вопросы аналитику, масштаб и многопериодность.

API принимает целые числа, исключая `bool`; отрицательный запас/спрос/минимальная
партия, неположительный приоритет/кратность, пустые ID и повтор ID внутри кейса
дают `ValueError`. Все заявки проверяются до распределения, даже при запасе 0.
Сопоставление CSV строго по `case_id`; дубликат строки запаса, неизвестный кейс,
ошибка колонок или нецелое число делают пакет неоднозначным и отклоняют его целиком.
Ошибки предметных ограничений в корректно прочитанных числах отклоняют только кейс.

## Проверка в чистом окружении

Для самого расчёта установка пакетов не требуется. Для тестов:

```sh
python -m venv .venv
```

Windows (PowerShell):

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q
```

Linux/macOS:

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

GitHub Actions запускает тесты на Python 3.10 и 3.13.
